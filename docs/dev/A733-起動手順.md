# Orange Pi 4 Pro（Allwinner A733）で Tamazusa を起動する手順（最初の段階）

最初の段階で確かめるのは、起動・GICv3・タイマ・PSCI・MMU・EL0 のプログラム（試験 M5〜M12）です。
ディスク・USB・画面・ネットワーク・Linux 互換層は、まだ入れていません。

> この手順は、ボードが届く前に、Orange Pi の公開している Linux と U-Boot のソースをもとに書いたものです。
> 実機で確かめていない点には「未確認」と書いています。違っていたら直します。

## 1. 用意するもの

| もの | 内容 |
|------|------|
| Orange Pi 4 Pro | 電源は USB Type-C の 5V（マニュアル v1.3）。PD には対応しない |
| microSD カード | 8GB 以上 |
| USB シリアル変換器 | **3.3V** のもの（5V のものは使わない）。デバッグ用の 3 本のピン（GND・TX・RX）につなぐ |
| 端末のソフト | 115200bps、8 ビット、パリティなし、ストップビット 1、フロー制御なし |

シリアルのつなぎ方: ボードの TX → 変換器の RX、ボードの RX → 変換器の TX、GND どうし。電源（3.3V・5V）の線はつながない。
デバッグ用のピンの位置は、ボードのマニュアルの図で確かめる（未確認）。

## 2. Image を作る（PC で）

```
cd ~/tamazusa-rv64-and-a64
make -f Makefile.a64 BOARD=a733 TEST_EXIT=0
```

`build-a733/Image` ができます。`TEST_EXIT=0` は、試験が終わっても電源を切らずに止まっておく指定です。

## 3. SD カードを用意する

いちばん簡単なのは、Orange Pi が配っている Linux（Debian か Ubuntu）のイメージを SD カードに書くことです。
U-Boot が入っているので、そのまま使えます。

1. Orange Pi の公式サイトから、Orange Pi 4 Pro 用の Linux のイメージを取ってきて、SD カードに書く（balenaEtcher など）。
2. いったんその Linux が起動することを確かめる（シリアルに U-Boot と Linux の表示が出る）。
3. SD カードを PC に差し、`/boot` のある区画に `Image` を `tamazusa.img` という名前で写す。
   Windows から見えない区画（ext4）の場合は、ボードの Linux の上で `scp` などで写してもよい。

## 4. U-Boot から起動する

1. ボードの電源を入れ、シリアルに U-Boot の表示が出たら、すぐに何かキーを押して自動起動を止める（`=>` が出る）。
2. 次を打つ（区画の番号・ファイルの場所は、イメージによって違うことがある。未確認）。

```
load mmc 0:1 0x42000000 /boot/tamazusa.img
booti 0x42000000 - ${fdtcontroladdr}
```

- `0x42000000` は、U-Boot がふだん Linux を読む番地（U-Boot の設定より）。`booti` が見出しを読んで、0x4020_0000 へ置き直す。
- `${fdtcontroladdr}` は、U-Boot 自身が使っているデバイスツリー。Tamazusa はいまのところデバイスツリーを読むだけなので、これで足りる。
- `load` が失敗するときは `ls mmc 0:1 /boot` や `ls mmc 0:2 /boot` で場所を探す。
- `booti` がないと言われたら、その U-Boot は使えない（知らせてください）。

## 5. うまくいったときの表示

```
Tamazusa AArch64 (Allwinner A733, Orange Pi 4 Pro)
[board_init] MPIDR 0x...  MIDR 0x...  DTB 0x...
[board_init] GIC OK (GICv3, system registers)
[psci] entered at EL2, calling the firmware with SMC
[psci] version 1.x
[psci] CPU_SUSPEND yes, SYSTEM_SUSPEND ..., SYSTEM_OFF yes, SYSTEM_RESET yes
[board_init] MMU on
[M5] ...
...
[M12] PASS
[TEST] ALL PASS
```

`SYSTEM_SUSPEND` が yes か no かは、ノートの「スリープ」の作り方を決める大事な結果です（仕様書の第 5 節）。

## 6. 止まったときの見分け方

| 最後に出た表示 | 考えられること |
|----------------|----------------|
| `Starting kernel ...` のあと何も出ない | UART の番地が違う、または読み込み先がずれている。表示をそのまま知らせてください |
| `[board_init] MPIDR ...` まで | GIC の番地や設定の違い |
| `GIC NG` | GICv3 の CPU の窓口が使えない（ファームウェアの設定） |
| `[psci] ...` のあと止まる | MMU を有効にするところ |
| `[M6]` で止まる・時間がおかしい | タイマの割込み（番号 30）が来ない |

どこで止まっても、シリアルの表示を最初から最後までそのまま送ってもらえれば、次の手を考えます。

## 7. 調べた出典

- Orange Pi の Linux（orange-pi-5.15-sun60iw2）の A733 のデバイスツリー: UART0 0x0250_0000（SPI 2）、GICD 0x0340_0000、GICR 0x0346_0000、タイマ 24MHz、PSCI は smc
- Orange Pi の U-Boot（v2018.05-a733）: RAM は 0x4000_0000 から、Linux を読む番地 0x4200_0000
- Orange Pi 4 Pro のユーザーマニュアル v1.3: 電源 Type-C 5V（PD なし）、デバッグ用 UART 115200bps
