# T88-BASIC の拡張（構造化・ON TIMER・機器の制御）

T88-BASIC は N88-BASIC 互換の BASIC です。そのうえで、N88 のあとに BASIC が身につけた力のうち、
機器の制御に役立つものを取り入れました。N88 のプログラムは今までどおり動きます。

- 新しい命令（DO・CASE・SUB など）は、名前の一部からは切り出しません。`DOG`・`DOT`・`SUBTOTAL` は今までどおり変数です。
  ただし、新しい命令と同じ名前の変数（`DO`・`IS`・`CASE`・`TIMER` など）は使えなくなります。
- 行番号は今までどおり要ります。

## 1. 構造化

| 書き方 | 意味 |
|--------|------|
| `IF 条件 THEN` … `ELSEIF 条件 THEN` … `ELSE` … `END IF` | 複数行の IF。`THEN` で行が終わると複数行になる。`ELSE` は行の最初に書く。`ENDIF` でもよい |
| `SELECT CASE 式` … `CASE 値, 値` … `CASE a TO b` … `CASE IS < x` … `CASE ELSE` … `END SELECT` | 場合分け。文字列もよい |
| `DO [WHILE 条件 \| UNTIL 条件]` … `LOOP [WHILE 条件 \| UNTIL 条件]` | くり返し。条件は前でも後ろでもよい |
| `EXIT DO`・`EXIT FOR`・`EXIT SUB`・`EXIT FUNCTION` | 途中で抜ける |
| `SUB 名前(引数, …)` … `END SUB` | 手続き。`CALL 名前(引数)` か `名前 引数` で呼ぶ |
| `FUNCTION 名前(引数, …)` … `名前 = 値` … `END FUNCTION` | 関数。式の中で `名前(引数)` と呼ぶ（引数がなくても `()` を付ける）。再帰もできる |
| `LOCAL 変数, …` | SUB・FUNCTION の中だけの変数 |

変数の扱いは BBC BASIC と同じです。引数と `LOCAL` の変数は、呼んでいるあいだだけの値で、戻ると元に戻ります。
ほかの変数は、プログラムのどこからでも同じものです（N88 のプログラムの書き方に近い）。引数は値で渡します。配列は渡せません。

```basic
10 PRINT FACT(10)
20 CALL HELLO("Taro", 2)
30 END
100 FUNCTION FACT(N)
110   IF N <= 1 THEN FACT = 1 ELSE FACT = N * FACT(N - 1)
120 END FUNCTION
200 SUB HELLO(NM$, K)
210   LOCAL J
220   FOR J = 1 TO K: PRINT "Hello "; NM$: NEXT
230 END SUB
```

## 2. ON TIMER（一定の間隔で呼ぶ）

| 書き方 | 意味 |
|--------|------|
| `ON TIMER(秒) GOSUB 行` | 間隔を決める（0.1 秒のような小数もよい） |
| `TIMER ON`・`TIMER OFF`・`TIMER STOP` | 始める・やめる・止めておく（STOP のあいだに来た時間は覚えておき、ON で呼ぶ） |
| `TIMER` | 真夜中からの秒（関数） |

- 処理（GOSUB の先）を実行しているあいだは、次の呼び出しを待たせます。遅れた分をまとめて呼ぶことはしません。
- `SLEEP` の途中で時間が来たら、先に処理を呼び、戻ってから残りの時間を待ちます（SLEEP の長さは変わりません）。
- `INPUT` で打ち込みを待っているあいだは呼びません。

## 3. 機器の制御

機器は Tamazusa の `/dev/io` を通して動かします。この章の番号の書き方（`PWM 0,50` など）は、QEMU の上の**仮想の機器**を指します。
ヒーターを入れると温度が上がり、ポンプを回すと水位が上がるので、温室・水槽・搬送・ロボットアームのプログラムを QEMU だけで試せます。
本物のボードや SoM のピンを動かすときは、名前の書き方（`PWM "HEATER",50`）を使い、名前と実物の結びつけを `/etc/io.conf` に書きます（6 章）。
ふつうの Linux で T88-BASIC を動かしたときは、同じ管理と仮想の機器を BASIC の中で動かします。

| 書き方 | 意味 |
|--------|------|
| `SENSOR(n)` | センサーを読む。0 温度（℃）1 湿度（%）2 水位（mm）3 距離（mm）4 明るさ（lx）5 音（dB）6 触覚（0/1）7 CO2（ppm）8 pH |
| `PWM ch,割合` / `PWM(ch)` | アクチュエータを 0〜100% で動かす / 今の値。0 ヒーター 1 ファン 2 ポンプ 3 照明 4 モーター（搬送） |
| `SERVO ch,角度[,速さ]` / `SERVO(ch)` | サーボ 0〜63 を −180〜180 度へ（速さは度/秒、全部のサーボで共通、初めは 90）/ 今の角度 |
| `ESTOP` / `ESTOP 0` / `ESTOP` | 非常停止 / 解く / 状態（関数。0 ふつう、1 非常停止、2 ウォッチドッグ、3 まだ動かさない） |
| `WATCHDOG ミリ秒` | この時間、どの機器にも書かなければ非常停止（0 でやめる） |
| `INP(ポート)`・`OUT ポート,値` | N88 と同じ書き方で、&HE000〜&HE07F の番号を読み書きする（下の表） |
| `MOVE x,y,z,f` | 3 軸の直線移動の距離と時間を計算して表示する（mm、mm/分。機器には出さない） |
| `JOINTS n`・`MOVEJ q1,…,qn,v` | 関節の数を決め、全関節が同時に着く時間を計算して表示し、サーボ 0〜n−1 に目標を出す |

**安全のための決まり**（7 章も）

- 起動したときは「まだ動かさない」（`ESTOP` が 3）です。出力するプログラムは、初めに `ESTOP 0` と書きます。
- 非常停止のあいだは、アクチュエータとデジタル出力は 0、サーボはその場で止まります。0 以外を出そうとするとエラー（111 Emergency stop）です。
- プログラムがエラーや中断（Ctrl-C・STOP）で止まると、アクチュエータを 0 にし、サーボをその場で止めます。
- ウォッチドッグは、BASIC が固まっても出力を止めるためのものです。カーネルのタスクが 10 ミリ秒ごとに見ています。
  非常停止のボタンは、ハードウェアで別に要ります。

**ポートの表**（`OUT &HE000+番号,値`・`INP(&HE000+番号)`。中身は `include/vio_sim.h`）

| 番号 | 中身 |
|------|------|
| 00〜08 | センサー（温度と pH は 0.1 の単位）。書くと値を置き換える（試験や授業の「もしも」に） |
| 10〜14 | アクチュエータ（%） |
| 20 | デジタル出力（16 ビット。信号機・LED など） |
| 3C | サーボの速さ（度/秒） |
| 3E | ウォッチドッグ（ミリ秒） |
| 3F | 非常停止（1 止める、0 解く。読むと状態） |
| 40〜7F | サーボ 0〜63 の目標（0.1 度）。読むと今の角度 |

番号を &HE000 からにしたのは、PC-9801 の I/O ポート（&H00〜&HFF のあたり）を叩く古いプログラムが、
間違って非常停止などを動かさないためです。

## 4. 向くもの・向かないもの

向くのは、遅くて、止まっても安全なものです。温室・水槽・鉄道模型・小さな搬送や仕分け・サーボのロボットアーム・理科の計測など。
1 秒ごとに見て判断する制御なら、BASIC で十分です。

向かないのは、CNC のような正確なパルスの同期や、二足歩行のつり合いのような速い制御です。BASIC はインタプリタなので、
実行の時間がゆれます。そうしたものは、カーネルのタスク（C）にパルスやサーボの制御を持たせ、BASIC からは目標の値を渡すだけにします。

## 5. 例

- `/bas/GREEN.BAS`: ビニールハウスの見張り（ON TIMER・SELECT CASE・SUB・ウォッチドッグ）
- `/bas/ARM.BAS`: 3 関節のロボットアーム（DO LOOP・SUB・LOCAL・SERVO）
- `/bas/TEST3.BAS`: 拡張の自己テスト（名前の口・上限も）

名前の口の例:

```basic
10 ESTOP 0
20 IF DEVICE("BLED") THEN PIN "BLED",1          ' USB の I/O ボードがつながっていれば、ボードの LED を点ける
30 PWM "HEATER", 50
40 PRINT ADC("TEMP")
50 SERVO "ARM0", 45                              ' io.conf の速さの上限（毎秒 180 度）で動く
```

## 6. 入出力の仕様（名前の口と /etc/io.conf）

### 6.1 考え方

- 言語が知るのは「口の種類」（デジタル・アナログ・PWM・サーボ）だけ。ヒーター・温度のような用途は、言語は知らない。
- プログラムは口を**名前**で呼ぶ。名前と実物（どのボードのどのピンか）の結びつけは、プログラムの外の**設定ファイル** `/etc/io.conf` に書く。
  ボードを替えたら、直すのは設定ファイルだけで、プログラムはそのまま動く（IEC 61131-3 で、番地 `%QX0.1` に名前を付けて使うのと同じ考え方）。
- 値は物の単位（℃・%・度・mm）で扱う。生の値からの換算は、設定ファイルの `scale`・`offset` でする。
- 言語が約束する時間は粗くしておく。サーボの速さのような時間で動かすものは、カーネルが受け持つ。

### 6.2 命令

| 種類 | 命令 | 例 |
|------|------|----|
| デジタル入出力 | `PIN 名前,0 か 1`・`PIN(名前)` | LED・リレー・スイッチ |
| アナログ入力 | `ADC(名前)` | 温度・明るさのセンサー |
| PWM 出力 | `PWM 名前,割合` / `PWM(名前)` | ヒーター・ファン・モーターの強さ |
| サーボ | `SERVO 名前,角度[,速さ]` / `SERVO(名前)` | ロボットアームの関節 |
| 調べる | `DEVICE(名前)` | その名前があり、実物もつながっていれば −1、なければ 0 |

名前は文字列か、名前を入れた変数で書く（`PWM "HEATER",50`、`N$="TEMP":PRINT ADC(N$)`）。
番号の書き方（`PWM 0,50`・`SERVO 0,90`・`PIN 2,1`・`ADC(0)`・`SENSOR(0)`）は、仮想の機器の決まった口を指す（互換のため残す）。
種類の合わない命令（ADC の口に `PWM`、入力の口に `PIN 名前,1` など）はエラー（5）。
通信でつなぐセンサー（I²C・SPI・シリアル）の命令は、まだない。

### 6.3 設定ファイル `/etc/io.conf`

```
# 名前   = 実物            上限・換算など
HEATER  = vio.pwm0
TEMP    = vio.adc0        unit C
ARM0    = vio.servo0      min -90  max 90  speed 180
BKNOB   = usbio.adc0      scale 0.09775  unit %
RELAY   = gpio20          invert
```

| 書くこと | 意味 |
|----------|------|
| 実物 | `vio.adcN・pwmN・servoN・pinN`（仮想の機器）、`usbio.pinN・adcN・pwmN・servoN`（USB の I/O ボード。N はボードのピン、adc はアナログの番号）、`som.pinN・pwmN・servoN`（SoM のピン。`gpioN`・`pwmN` とも書ける） |
| `min`・`max` | 出力の上限（物の値）。プログラムはこれを超えられない（名前でも番号でも同じ） |
| `speed` | サーボの速さの上限（度/秒）。プログラムが速さを言わなければ、この速さで動く |
| `scale`・`offset` | 物の値 = 生の値 × scale + offset |
| `input`・`output` | ピンの向き（ピンは初めは output） |
| `invert` | 0 で電気が入るつなぎ方。1 と 0（PWM は 100% と 0%）を入れ替える。止めるときも、切れる側にする |
| `unit` | 単位（説明のため） |

- ディスクの `/etc/io.conf` を、起動のときに 1 回だけ読む。ないときは同じ中身の組み込みの結びつけを使う。まちがった行は飛ばして、起動のときに知らせる。
- いまはディスクが読み取り専用なので、書き換えるのはディスクを作るとき（`user/disk/etc/io.conf`）。これが、機械を据え付けた人だけが上限を決められる、ということの今の形である。

### 6.4 実物（中身）

| 中身 | 何か | 見つけ方 |
|------|------|----------|
| `vio` | 仮想の機器（温室・水槽・搬送・サーボ 64 個の計算） | いつもある |
| `usbio` | USB でつないだマイコンのボード。Firmata（マイコンボードを USB 越しに動かす、広く使われている決まり）で動かす。ボードに StandardFirmata を書き込んでおく | USB シリアル（FTDI・CDC-ACM）を見つけ、Firmata の問い合わせに答えたら |
| `som` | SoM のピン。デバイスツリーに書かれた、知っている装置を使う: DesignWare の APB GPIO（`snps,dw-apb-gpio`）、SiFive の GPIO（`sifive,gpio0`）、SiFive の PWM（`sifive,pwm0`） | 起動のとき、OpenSBI から渡されたデバイスツリーを読んで |

- `usbio`・`som` のサーボは 0〜180 度（パルス幅 544〜2400 マイクロ秒。Arduino の Servo と同じ）。`vio` のサーボは −180〜180 度。
- `usbio` の Arduino Uno では、ピンの番号はボードの D0〜D13、アナログは A0〜A5（adc0〜adc5）。
- `som` の番号は、デバイスツリーに書かれた順に、GPIO の線と PWM のチャンネルを通しで数えたもの。
  SiFive の PWM は 4 チャンネルで周期が共通なので、同じブロックで PWM とサーボを混ぜるとエラー（5）。
- 知らない装置の SoM では、`som` は現れない（そのドライバを足す）。
- **確かめたこと**: `usbio` は QEMU の USB シリアルに Firmata のボードの模擬（`tools/firmata_sim.py`）をつないで、`som` はメモリの上の偽のレジスタと作ったデバイスツリーで確かめた。本物のボード・SoM ではまだ確かめていない。

### 6.5 エラー

| 状況 | エラー |
|------|--------|
| その名前がない、実物がつながっていない | 110 Device unavailable |
| 上限・範囲の外、種類が合わない | 5 Illegal function call |
| 非常停止・ウォッチドッグ・まだ動かさないあいだに、0 以外を出そうとした | 111 Emergency stop |
| 機器を動かす権限がない・ネットワークを使うプロセスから動かそうとした（7.2 の 6） | 112 Permission denied |

## 7. 安全

### 7.1 基本の立場

機械の安全の規格（ISO 12100・IEC 60204-1 など）がかかるのは、言語やコンピュータではなく、機械を作って使わせる人です。
それでも、この言語と OS は、**正しい使い方だけでなく、合理的に予見できる誤った使い方**（ISO/IEC Guide 51 の言葉）まで考えて、危険を減らす作りにする。

目指すのは、事故を起こしにくくし、悪用の手間を増やし、責任の所在をはっきりさせることである。
ピンを入れたり切ったりする機能そのものは、どのマイコンにもある。悪意のある使い方を、言語の作りだけで完全に止めることはできない。
それを目指して、正しく使う人を不便にすることはしない。

### 7.2 決まり

| # | 決まり | いま |
|---|--------|------|
| 1 | エラーや中断でプログラムが止まったら、アクチュエータを 0 にし、サーボをその場で止める | 実装済み |
| 2 | 非常停止のあいだは、出力を変えられない | 実装済み |
| 3 | ウォッチドッグ: 決めた時間、どの機器にも書かなければ非常停止（すべての中身の出力を止める） | 実装済み |
| 4 | 上限は機械の持ち主が `/etc/io.conf` に書き、プログラムはそれを超えられない（超えるとエラー） | 実装済み（名前でも番号でも） |
| 5 | 起動したときは、出力はすべて 0。動かすには、はっきり解除する（`ESTOP 0`） | 実装済み |
| 6 | `/dev/io` に触れる利用者を、ファイルの権限で限る。ネットワーク越しに機器を動かすことは、初めは許さない | 実装済み（7.6） |
| 7 | いつ、どのプログラムが、どの口に何を出したかを記録する | 実装済み（7.7） |
| 8 | ウォッチドッグを、カーネルのタイマー（実機ではハードウェア）で動かし、BASIC やカーネルが固まっても出力を止める | 半分: カーネルのタスクが 10 ミリ秒ごとに見る（BASIC が固まっても止まる）。カーネルが固まったときのハードウェアのウォッチドッグは実機の段階 |

### 7.3 ハードウェアの非常停止

`ESTOP` は、ハードウェアの非常停止の**代わりにならない**。人のいる所で動く機械には、プログラムに頼らない非常停止（押しボタンと、動力を直接切る配線）を、別に付けること。

### 7.4 使ってはいけない用途

次の用途には使わないこと。説明書と使用許諾にも書く。

- 人の命や体の安全が、この言語と OS の正しい動きにかかっているもの（医療機器、乗り物の運転、人を乗せる機械、昇降機など）
- 人や動物を傷つけること、他人の財産を壊すことを目的とするもの
- 法令で決められた安全の認証が要る機械への、認証のない組み込み

この言語と OS は、温室・水槽・模型・小さな搬送・教育や実験の計測のような、遅くて、止まっても安全なものを動かすためのものである。

### 7.5 説明書に書くこと

危険と使い方の限界を説明書に書くことは、設計の一部である。少なくとも次を書く。
7.3 のハードウェアの非常停止が要ること、7.4 の使ってはいけない用途、BASIC は実行の時間がゆれること（4 章）、仮想の機器と実物の違い、上限の設定のしかた。

### 7.6 誰が動かせるか（決まり 6）

- **読む**（`ADC`・`PWM(名前)` など）のは誰でもできる。**止める**（`ESTOP`、エラーで止まったときの安全な状態）のも誰でもできる。
- **動かす**（出力・`ESTOP 0` の解除・`WATCHDOG` の設定）のは、root か、`/etc/io.conf` の `access group` のグループ（既定は 20 = `/etc/group` の `io`）の人だけ。`/dev/io` は `crw-rw-r--`（root・io）に見える。
- **ネットワークのソケットを開いたプロセスと、その子**（ssh で入った人のシェルや BASIC、ネットワークから命令を受けるプログラム）は、動かせない。読むことと止めることはできる。
  機械の持ち主が、危険がないと判断したときだけ、`/etc/io.conf` に `network allow` と書いて許す（既定は `network deny`）。
- 断られると、BASIC はエラー 112 Permission denied、C のプログラムは `EACCES` を受け取る。断ったことも記録に残る。
- いまの Tamazusa は、ふだんは root だけで使っている。uid・gid はプロセスごとに持ち（setuid・setgid・setgroups で変えられ、root でなくなると戻れない）、fork と execve で引き継ぐ。

### 7.7 記録（決まり 7）

- 記録するもの: 解除（ARM）・停止（STOP）・安全な状態へ（SAFE）・名前の口への出力（SET、値が変わったときだけ）・番号の口への出力（OUT）・ウォッチドッグの設定（WDT）と、ウォッチドッグで止まったこと（WATCHDOG）・断ったこと（DENY-PERM・DENY-NET）。
- 1 行の形: `2026-11-15T17:14:14.562+09:00 pid 176 iotest uid 0 SET HEATER 30.000`（日本時間の日時・プロセスの番号・プログラムの名前・uid・ネットワークからなら net・操作・口・値）。
- カーネルの中に 256 件までためる。`cat /dev/iolog` で読める（古いものから）。`/data`（書き込めるディスク）があれば、1 秒ごとに `/data/log/io.log` に書き足すので、電源を切っても残る。
- 記録は、事故のあとに何があったかを確かめるためのもの。記録があっても、7.3 のハードウェアの非常停止の代わりにはならない。

## 8. 来歴と互換性

- T88-BASIC は、独自に実装したものである。N88-BASIC との互換性を確保するため、NEC 発行の N88-BASIC の資料を参照した。
